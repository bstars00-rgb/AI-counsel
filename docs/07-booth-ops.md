# 07 · 부스 운영 + 테스트 시나리오

## 7.1 부스 사전 점검 체크리스트 (D-1)

```
□ 부스 디바이스 (태블릿/노트북) 준비 — 가로 1280x800 이상 권장
□ 디바이스 브라우저: Chrome / Safari / Edge 최신 버전 설치
□ 시연 URL 결정:
    ─ 옵션 A: https://bstars00-rgb.github.io/AI-counsel/  (GitHub Pages, Mock)
    ─ 옵션 B: 로컬 index.html (USB 백업)
    ─ 옵션 C: Vercel URL (Claude API 사용 시)
□ 시연 URL 즐겨찾기 등록 + 시작 페이지 설정
□ 전체화면 모드 단축키 확인 (F11 / Cmd+Ctrl+F)
□ index.html 백업본 USB 에 1개 이상 복사 (인터넷 끊김 대비)
□ 부스 Wi-Fi 안정성 점검 — Claude API 사용 시
□ 부스 PC 에 한국어 입력기 활성화 (생년월일 직접 입력 가능하도록)
□ 자동 잠금 / 절전 모드 비활성화 (윈도우: 설정 > 전원)
□ 마우스 / 터치 모두 동작 확인 (시진 버튼 클릭)
□ 테스트 시나리오 (§ 7.3) 전부 1회씩 실행
□ 부스 운영자 / 사회자 매뉴얼 (§ 7.4) 인쇄 1부
```

## 7.2 부스 오픈 당일 체크리스트

```
□ 디바이스 켜기 → 전체화면 모드로 시연 페이지 띄움
□ 결과 화면까지 1회 시연 후 "처음으로" 클릭 (입력 폼 노출 상태로 대기)
□ 입력 필드 모두 비어 있는지 확인
□ Wi-Fi 연결 상태 (Live 모드 사용 시)
□ 백업 디바이스 1대 준비 (장애 대비)
```

## 7.3 수동 테스트 시나리오

### 7.3.1 가장 기본 흐름 (Happy Path)

| Step | 동작 | 기대 결과 |
|---|---|---|
| 1 | 페이지 로드 | view = `input`, 헤더 + 입력 폼 표시 |
| 2 | 이름 입력: "테스트" | 제출 버튼 여전히 비활성 (생년월일 미입력) |
| 3 | 생년월일 선택: "1990-05-15" | 제출 버튼 활성화 (오렌지) |
| 4 | 태어난 시 "오시" 클릭 | "오시" 버튼이 오렌지 보더 + 배경으로 변경 |
| 5 | "오늘의 사주 여행지 보기" 클릭 | view = `loading`, ✨ 펄스 애니메이션 + "테스트 님의 사주를 살피고 있어요" |
| 6 | 0.7~1.2초 후 | view = `result`. 헤드라인 + 별점 + 키워드 + 4 카테고리 + 추천 도시 + 호텔 카드 + 행운 요소 + 클로징 |
| 7 | 추천 도시 확인 | 25개 풀 중 하나 (일본/한국/베트남) |
| 8 | 호텔 카드 확인 | TOP 1, 2, 3 표시 (도시 내 순서). 도시 내 호텔이 1개뿐이면 TOP 1 만 |
| 9 | "다른 사주로 다시 보기" 클릭 | view = `input`, **입력 폼 값 유지** (테스트 / 1990-05-15 / 오시) |
| 10 | "처음으로" 클릭 (결과 화면에서) | view = `input`, **입력 폼 초기화** (모두 비어있음, 시진 = 모름) |

### 7.3.2 결정론성 테스트 (Mock 모드)

같은 입력 + 같은 날짜로는 항상 같은 결과여야 합니다.

| Step | 입력 | 기대 |
|---|---|---|
| 1 | "김민지" / 1992-08-15 / 오시 | 결과 A 캡처 |
| 2 | "처음으로" → 동일 입력 다시 | 결과 A 와 완전히 동일 |
| 3 | "처음으로" → "김민지" / 1992-08-15 / **묘시** | 결과 B (A 와 다름, 시진 영향) |
| 4 | "처음으로" → "**김민**" / 1992-08-15 / 오시 | 결과 C (이름 한 글자 차이로도 다름) |

### 7.3.3 25개 도시 풀 검증 (장기 시연 시)

여러 번 시연하면서 한 번씩이라도 등장하는지:
- 일본 도시 8개: 도쿄/오사카/교토/후쿠오카/삿포로/오키나와/고베/나고야
- 한국 도시 8개: 서울/부산/제주/여수/속초/강릉/양양/경주
- 베트남 도시 9개: 다낭/나트랑/호이안/푸꾸옥/하노이/호치민/달랏/무이네/사파

도시 분포는 시드 해시 기반이라 매 입력마다 거의 균등하게 분포.

### 7.3.4 호텔 데이터 검증

| Step | 입력 | 추천 도시 | 기대 호텔 |
|---|---|---|---|
| 1 | 임의 입력 | 도쿄 | ICI HOTEL Tokyo Hatchobori / Sotetsu Grand Fresa Tokyo - Bay Ariake / SOTETSU GRAND FRESA TAKADANOBABA (또는 순서 다름) |
| 2 | 임의 입력 | 경주 | TOP 1 만 표시됨 (경주 호텔 1개뿐) |
| 3 | 임의 입력 | 오키나와 | Naha 또는 Chatan 의 호텔 (둘 다 매칭됨) |

### 7.3.5 12 시진 입력 검증

| 시진 | 시간 |
|---|---|
| 자시 | 23:00 - 01:00 |
| 묘시 | 05:00 - 07:00 |
| 오시 | 11:00 - 13:00 |
| 술시 | 19:00 - 21:00 |

각 시진 선택 시 결과의 fortune_summary 첫 부분이 시진 분위기를 반영해야 함 (Mock 모드 기준 § 4.2 표 참고).

### 7.3.6 입력 검증 / 오류 처리

| Step | 동작 | 기대 |
|---|---|---|
| 1 | 이름 비우고 제출 | 제출 버튼 비활성 (클릭 안 됨) |
| 2 | 생년월일 비우고 제출 | 제출 버튼 비활성 |
| 3 | 이름 40자 초과 시도 | `maxlength=40` 으로 잘림 |
| 4 | 생년월일 미래 날짜 선택 | input 의 `max` 가 오늘이라 자동 차단 |
| 5 | Claude API 실패 (Vercel 등) | mode = `mock-fallback`, 그래도 결과 화면 표시 |

### 7.3.7 반응형 / 디바이스 검증

| 화면 | 기대 |
|---|---|
| 노트북 1366×768 이상 | 시진 grid 4열, 카테고리 4열 |
| 태블릿 세로 768×1024 | 시진 grid 3열, 카테고리 2열 |
| 모바일 (참고) | 단일 컬럼, 호텔 카드 세로 |

### 7.3.8 접근성 (간단 체크)

- 키보드 Tab 으로 모든 입력/버튼 이동 가능한지
- Enter 키로 폼 제출 동작
- 별점 표시에 `aria-label="{score}/5"` 적용됨

## 7.4 부스 운영자 매뉴얼 (인쇄용 요약)

```
═════════════════════════════════════════════════════════
  오마이치 사주 여행지 — 부스 운영 가이드
═════════════════════════════════════════════════════════

[1] 시연 권유 멘트 예시
   "오마이호텔 트래블쇼 부스에 오신 걸 환영합니다!
    이름과 생년월일, 태어난 시간만 알려주시면 오마이치가
    오늘 어울리는 여행지와 호텔을 30초 안에 골라드려요.
    한 번 해보시겠어요?"

[2] 입력 단계 도움말
   - 태어난 시는 모르면 "모름" 으로 두셔도 OK
   - 생년월일은 달력 아이콘 클릭해서 선택
   - 이름은 본명/별명 모두 OK

[3] 결과 화면 활용
   - 추천 도시 → "이 도시는 OOO 이 매력이에요" (vibe 참고)
   - 호텔 카드 → "저희 오마이호텔 Top 100 안에 든 호텔들이에요"
   - 인스타 공유 권유: "헤드라인이 마음에 들면 캡처해 가세요"

[4] 결과 후 종료 / 다음 손님
   - "다른 사주로 다시 보기" → 같은 손님 다른 입력
   - "처음으로" → 다음 손님

[5] 장애 대처
   - 화면이 멈춤 / 빈 화면: F5 새로고침
   - 그래도 안 되면 백업 노트북으로 전환
   - URL: https://bstars00-rgb.github.io/AI-counsel/
   - 오프라인 백업: USB > index.html

[6] 자주 묻는 질문
   Q. "정통 사주 맞아요?"

   Q. "제 정보 저장되나요?"
   A. "저장 안 됩니다. 결과 보고 다른 손님 차례 되면 자동으로 비워져요."
```

## 7.5 알려진 제약 / 주의 사항

### 7.5.1 정통 명리학 아님

- 천간/지지/오행을 분위기 한 마디로만 활용
- 만세력 / 대운 / 십성 등 정통 사주 요소 없음
- 결과는 "재미용 마케팅 콘텐츠"로 안내 필요 (footer 명시됨)

### 7.5.2 점수 분포

- Mock 모드 점수는 항상 3~5 (1, 2는 안 나옴) — 부정적 결과 회피
- Claude API 모드도 시스템 프롬프트에서 평균 3.5~4.5 후하게 안내

### 7.5.3 도시 풀 제한

- 25개 도시 외 추천 불가 (Claude enum 강제, Mock 도 풀에서만 선택)
- 동남아 외 (필리핀, 태국, 대만 등) 의도적 미포함

### 7.5.4 호텔 데이터 정적

- xlsx 갱신 전까지 호텔 데이터 고정
- 가격/공실/할인 정보 없음 (영업 트리거가 아닌 인지도용)

### 7.5.5 개인정보

- 입력값은 메모리에만, 페이지 새로고침 시 휘발
- Claude API 사용 시 입력값이 Anthropic 서버에 전달됨 (footer 안내)
- 저장 / 추적 / 마케팅 자동화 없음

### 7.5.6 GitHub Pages 한계

- 정적 호스팅 → Claude API 호출 불가 (Mock 전용)
- xlsx 원본 파일은 raw URL 로 다운로드 가능 (영업 정보 노출 시 주의)

### 7.5.7 시간대

- "오늘 날짜" 는 서버 시간 (Vercel = UTC) 또는 브라우저 시간 (Mock = client)
- 부스가 한국 시간으로 운영되므로 큰 문제 없음, 다만 UTC 자정 직후 결과가 살짝 달라질 수 있음

## 7.6 향후 개선 후보 (백로그)

- 마스코트 PNG (`mascot.png`) 실 디자인 교체 (현재 이모지 폴백)
- 회사 로고 PNG (`logo.png`) 실 SVG/PNG 교체
- 인스타 공유 카드 자동 생성 (html2canvas 등)
- 음성 입력 (Web Speech API) — 부스 손 자유로움
- 다국어 (영/일/베트남어) — 외국인 방문객 대응
- 결과 QR 코드 — 손님이 자기 폰으로 가져갈 수 있게
- 호텔 데이터 도시별 더 풍부하게 (10개씩)
- 시진 입력 보조 — "1990년 5월 15일 오전 11시 30분" → 사시 자동 변환

## 7.7 문의 / 에스컬레이션
